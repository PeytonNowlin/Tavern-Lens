## 1. macOS log locations and configuration

### 1.1 log.config path
- **HSTracker** hard-codes `~/Library/Preferences/Blizzard/Hearthstone/log.config` in `CoreManager.configPath` ([HST/HSTracker/Logging/CoreManager.swift#L482-L485](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/CoreManager.swift#L482)).
- **HDT** (Windows) uses `%LOCALAPPDATA%\Blizzard\Hearthstone\log.config`. Non-default clients launched with `-uid <product>` get their own subdirectory, and `hs_beta` counts as the default ([HDT/Hearthstone Deck Tracker/Utility/LogConfig/LogConfigConstants.cs](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/Utility/LogConfig/LogConfigConstants.cs)). On this Mac the client runs with `-uid hs_beta`, so the default path applies.

### 1.2 Sections and options each tracker enables

| Tracker | Sections | Options per section | Verbose |
|---|---|---|---|
| HSTracker | `Power`, `Rachelle`, `Arena`, `LoadingScreen`, `Decks`, `FullScreenFX` (`LogLineNamespace.usedValues()`, [HST/HSTracker/Logging/LogLineNamespace.swift](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogLineNamespace.swift)) | `LogLevel=1`, `FilePrinting=true`, `ConsolePrinting=false`, `ScreenPrinting=false` ([HST/HSTracker/Logging/LogLineZone.swift](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogLineZone.swift)) | `Verbose=true` **only for Power** (`let requireVerbose = [LogLineNamespace.power]`, [CoreManager.swift#L138](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/CoreManager.swift#L138)) |
| HDT | `Achievements`, `Arena`, `FullScreenFX` (the code says it has been unused since HS 25.0 and is kept only so that log.config does not need rewriting), `LoadingScreen`, `Power` ([LogConfigConstants.cs `RequiredConfigItems`](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/Utility/LogConfig/LogConfigConstants.cs)) | `LogLevel=1`, `FilePrinting=true`; `ConsolePrinting` comes from a config setting (`LogConfigConsolePrinting`, default false) | `Power` only (`Verbose => new [] { "Power" }`) |

For a Battlegrounds reader, **only `Power` (with Verbose) and `LoadingScreen` matter.** Neither tracker reads `Zone.log`. On this Mac `Zone.log` grew to 6.2 MB within about 5 minutes of one BG game (compared with 3.6 MB for `Power.log`), so enabling it only costs disk I/O.

HSTracker's validation (`LogLineZone.isValid`) needs `requireVerbose == verbose`. Its parser splits sections on `[`, but only sections whose names are in `LogLineNamespace` are checked. So an extra `Verbose=true` on non-Power sections would make HSTracker rewrite the file.

### 1.3 Where logs are written today and how the session folder is found
- HSTracker's default Hearthstone path is `/Applications/Hearthstone` (`@UserDefault(key: Settings.hearthstone_log_path, defaultValue: "/Applications/Hearthstone")`, [HST/HSTracker/Core/Settings.swift#L202](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Core/Settings.swift#L202)).
- **HSTracker does not scan for the session folder. It asks HearthMirror (memory reading) for it:** `let logPath = MirrorHelper.getLogSessionDir()` ([CoreManager.swift#L63 and #L288](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/CoreManager.swift#L288)). If the mirror returns an empty string, it retries every 1 s. `MirrorHelper.initMirror` also waits for `getLogSessionDir()` to be non-empty ([HST/HSTracker/HearthMirror/MirrorHelper.swift#L38-L60](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/HearthMirror/MirrorHelper.swift#L38)). Each reader then opens `"\(logPath)/\(name).log"` ([HST/HSTracker/Logging/LogReader.swift](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogReader.swift)).
- **HDT finds the folder without memory reading.** It lists `<HS dir>\Logs\` (`HearthstoneLogsDirectoryName = "Logs"`), takes the subdirectory with the newest `CreationTime`, and checks that the folder is live by trying to `MoveTo` a file inside it. Windows locks files the game has open. The folder is re-checked every 5 s ([HDT/HearthWatcher/LogReader/LogFileWatcher.cs#L40-L92](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/HearthWatcher/LogReader/LogFileWatcher.cs#L40)). **The lock trick does not carry over to macOS**, because POSIX does not block renaming an open file. A logs-only macOS app should pick the newest `Logs/Hearthstone_*` folder, by name (the timestamp sorts lexically) or by birth time, while the Hearthstone process is running. A reasonable extra check is that `Power.log` or `Hearthstone.log` in that folder is still growing.
- Folder naming seen on this Mac: `Hearthstone_YYYY_MM_DD_HH_MM_SS` (e.g. `Hearthstone_2026_09_22_20_33_28`). A new folder is created on every client launch, and the old folders stay behind.

### 1.4 client.config (log size limit)
Both trackers write `client.config` in the Hearthstone install dir with exactly `[Log]\nFileSizeLimit.Int=-1`, which removes the client's per-file log size cap. If they had to create or change the file, they report that a restart is needed:
- HSTracker `Helper.ensureClientLogConfig()` writes `/Applications/Hearthstone/client.config` ([HST/HSTracker/Utility/Helper.swift#L59-L78](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Utility/Helper.swift#L59)).
- HDT `Helper.EnsureClientLogConfig()` ([HDT/Hearthstone Deck Tracker/Utility/Helper.cs#L787](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/Utility/Helper.cs#L787)).

Neither codebase states the default size limit. A late BG game produces a lot of output (see §6), so a Battlegrounds reader should also write this file.

### 1.5 Is a restart needed after writing log.config?
Yes. Both trackers treat log.config as being read only at client startup:
- In HSTracker, `setup()` rewrites log.config when sections are missing or wrong. If Hearthstone is already running, it returns `false` and marks logging as broken. The app shows `NotificationManager.showNotification(type: .restartRequired)` on launch or when HS starts if `ensureClientLogConfig()` changed anything ([CoreManager.swift#L56-L61, #L234-L262, #L418-L422](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/CoreManager.swift#L234)).
- HDT does the same (`ShowRestartRequiredMessageAsync()` / `Overlay.ShowRestartRequiredWarning()` when `!ok || logConfigUpdated`, [HDT/Hearthstone Deck Tracker/Core.cs#L455-L461](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/Core.cs#L455)).

## 2. Power.log format

### 2.1 Line grammar
Every line looks like `<Level> <HH:MM:SS.fffffff> <Method>() - <payload>`, where the level is `D`, `W` or `E`. The regexes are `TIMESTAMP_RE = ^([DWE]) ([\d:.]+) (.+)$` and `POWERLOG_LINE_RE = ([^(]+)\(\) - (.+)$` ([HSLOG/hslog/tokens.py](https://github.com/HearthSim/python-hslog/blob/015c0dec197779c90cd3131ecda2c990292342b6/hslog/tokens.py)). **Timestamps carry no date.** HDT maps each line to today and subtracts a day if the result is in the future ([HDT/HearthWatcher/LogReader/LogLine.cs#L25-L30](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/HearthWatcher/LogReader/LogLine.cs#L25)). Nesting is shown by indentation.

Method prefixes in Power.log:
- `GameState.DebugPrintPower()`: packets as they arrive from the server.
- `GameState.DebugPrintPowerList()`: `Count=N` header for each packet batch.
- `GameState.DebugPrintGame()`: game metadata (`BuildNumber=`, `GameType=`, `FormatType=`, `ScenarioID=`, `PlayerID=n, PlayerName=...`).
- `GameState.DebugPrintEntityChoices()` / `DebugPrintEntitiesChosen()` / `DebugPrintOptions()` / `SendChoices` / `SendOption`: choices (hero pick, discovers, trinkets, quests) and options.
- `PowerTaskList.DebugPrintPower()`: the same power stream, printed when the client **executes** each task list, in step with the animations.
- `PowerProcessor.EndCurrentTaskList()` / `PowerTaskList.DebugDump()`: task-list bookkeeping.

### 2.2 Packet types (python-hslog regexes, [HSLOG/hslog/tokens.py](https://github.com/HearthSim/python-hslog/blob/015c0dec197779c90cd3131ecda2c990292342b6/hslog/tokens.py))
- `CREATE_GAME`, followed by `GameEntity EntityID=n` and `Player EntityID=n PlayerID=n GameAccountId=[hi=.. lo=..]`, each with indented `tag=X value=Y` lines.
- `FULL_ENTITY - Creating ID=n CardID=xxx`, which is the `GameState` form. The `PowerTaskList` form is `FULL_ENTITY - Updating [entityName=.. id=.. zone=.. zonePos=.. cardId=.. player=..] CardID=..`, which is the form HDT/HSTracker `CreationRegex` matches.
- `SHOW_ENTITY - Updating Entity=<e> CardID=xxx` reveals a hidden entity. `HIDE_ENTITY - Entity=<e> tag=ZONE value=..` hides one again.
- `CHANGE_ENTITY - Updating Entity=<e> CardID=xxx` is a transform.
- `TAG_CHANGE Entity=<e> tag=<TAG> value=<V> [DEF CHANGE]`.
- `BLOCK_START BlockType=<T> Entity=<e> EffectCardId=.. EffectIndex=n Target=<e> SubOption=n [TriggerKeyword=..]` ... `BLOCK_END`. Block types include `PLAY`, `POWER`, `TRIGGER`, `ATTACK`, `DEATHS`, `FATIGUE` and `RITUAL`.
- `META_DATA - Meta=<MetaDataType> Data=<e> InfoCount=n`, followed by `Info[i] = <e>`.
- `SUB_SPELL_START - SpellPrefabGUID=.. Source=n TargetCount=n` / `SUB_SPELL_END`, `CACHED_TAG_FOR_DORMANT_CHANGE`, `VO_SPELL`, `SHUFFLE_DECK PlayerID=n` and `RESET_GAME`.

An entity is written as `GameEntity`, a player name/BattleTag, a bare id, or `[entityName=.. id=.. zone=.. zonePos=.. cardId=.. player=..]`. Hidden entities appear as `UNKNOWN ENTITY [cardType=INVALID]`. **The two streams format the same entity differently:** the live log shows `GameState ... TAG_CHANGE Entity=4 tag=BACON_COMBAT_DAMAGE_CAP_ENABLED value=1` next to `PowerTaskList ... TAG_CHANGE Entity=GameEntity tag=BACON_COMBAT_DAMAGE_CAP_ENABLED value=1`. **When the client has no name for a tag, it prints the number**, e.g. `tag=2022`, `tag=3533`, `tag=3148`.

### 2.3 Which stream to parse: PowerTaskList for state, GameState for metadata and choices
Both trackers use **the same split** (HSTracker [LogReaderManager.swift#L189-L214](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogReaderManager.swift#L189); HDT [LogWatcherManager.cs `OnNewLines`](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/LogReader/LogWatcherManager.cs#L124)):
- `GameState.*` lines are **stored raw for replay upload** (`game.add(powerLog:)` / `_game.PowerLog.Add`) and used only for `DebugPrintEntityChoices`/`DebugPrintEntitiesChosen` (the choices handler) and `DebugPrintGame` (player name to PlayerID).
- **Every other line, `PowerTaskList.DebugPrintPower` in practice, feeds the entity/tag state machine** (`powerGameStateParser.handle` / `_powerLineHandler.Handle`). The reader filters are `["PowerTaskList.DebugPrintPower", "GameState.", "PowerProcessor.EndCurrentTaskList"]`, and HDT adds `"ChoiceCardMgr."` ([HST LogReaderManager.swift#L76](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogReaderManager.swift#L76); [HDT LogWatcherManager.cs#L43-L47](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/LogReader/LogWatcherManager.cs#L43)).
- By contrast, **python-hslog parses only `GameState`** (`self._game_state_processor = "GameState"`, [HSLOG/hslog/parser.py#L191](https://github.com/HearthSim/python-hslog/blob/015c0dec197779c90cd3131ecda2c990292342b6/hslog/parser.py#L191)). It is an offline replay parser, so timing does not matter to it.

**Why PowerTaskList (timing measured on the live BG log).** The server sends a whole BG combat at once. `GameState` prints it as soon as it arrives, while `PowerTaskList` prints it as the client plays the animations:

| Event (turn 2 combat, then turn 3 recruit) | GameState ts | PowerTaskList ts |
|---|---|---|
| `GameEntity TURN=2`, `BOARD_VISUAL_STATE=2` (combat starts) | 20:36:19.14 | 20:36:19.23 |
| `tag=3533 value=0` | 20:36:19.36 | 20:36:20.74 |
| `tag=2022 value=0` | 20:36:19.70 | 20:36:23.54 |
| `BOARD_VISUAL_STATE=1` (back to shop) | 20:36:19.73 | 20:36:35.26 |
| `NEXT_OPPONENT_PLAYER_ID=3`, `TURN=3` | 20:36:19.93 | 20:36:38.03 |

So `GameState` has the **full combat result about 16–18 s before it is shown**. `PowerTaskList` matches what is on screen, which is what an overlay needs; this is why the trackers use it. A companion could read `GameState` on purpose to learn the combat outcome early, but that shows hidden information ahead of the UI and falls out of sync with the visuals.

## 3. Detecting Battlegrounds and match boundaries

### 3.1 GameType / FormatType values ([PYHS/hearthstone/enums.py#L1990-L2026](https://github.com/HearthSim/python-hearthstone/blob/637eaa29c911d6b3000349713b8847b035205fb7/hearthstone/enums.py#L1990))
- Solo: `GT_BATTLEGROUNDS = 23`, `GT_BATTLEGROUNDS_FRIENDLY = 24`, `GT_BATTLEGROUNDS_AI_VS_AI = 35`, `GT_BATTLEGROUNDS_PLAYER_VS_AI = 36`.
- Duos: `GT_BATTLEGROUNDS_DUO = 37`, `GT_BATTLEGROUNDS_DUO_VS_AI = 38`, `GT_BATTLEGROUNDS_DUO_FRIENDLY = 39`, `GT_BATTLEGROUNDS_DUO_AI_VS_AI = 40`, `GT_BATTLEGROUNDS_DUO_1_PLAYER_VS_AI = 41`.
- `BnetGameType` has matching `BGT_BATTLEGROUNDS = 50`, `BGT_BATTLEGROUNDS_DUO = 65`, and so on.
- FormatType is meaningless for BG. The live game reports `FT_WILD`.
- HSTracker's grouping: `isSoloBattlegroundsGameType` covers {bg, bg_friendly, bg_ai_vs_ai, bg_player_vs_ai} and `isBattlegroundsDuosMatch` covers {duo, duo_vs_ai, duo_friendly, duo_ai_vs_ai} ([HST/HSTracker/Logging/Game.swift#L2744-L2758](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/Game.swift#L2744)).

### 3.2 How the trackers get the game type
- **Both trackers get it from memory, not from the log.** HSTracker uses `MirrorHelper.getMatchInfo()` and sets `_currentGameType = matchInfo.gameType` ([Game.swift#L1310-L1329](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/Game.swift#L1310)). HDT loops `while((gameType = (GameType)HearthMirror.Reflection.Client.GetGameType()) == GT_UNKNOWN)` ([HDT/Hearthstone Deck Tracker/Hearthstone/GameV2.cs#L427-L434](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/Hearthstone/GameV2.cs#L427)).
- **Known memory bug:** the mirror can return a stale *solo* type for a Duos game. HSTracker corrects this by checking whether any player entity has `BACON_DUO_TEAM_ID > 0` ([Game.swift#L1135-L1160 `tryCorrectMisreadSoloGameType`](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/Game.swift#L1141)).
- **A logs-only reader can get it directly from `GameState.DebugPrintGame() - GameType=GT_BATTLEGROUNDS`**, which is printed right after `CREATE_GAME` (live sample above). python-hslog parses exactly this (`handle_game`: keys `GameType` and `FormatType` go to enums, and other keys such as `BuildNumber` and `ScenarioID` go to int; [HSLOG/hslog/parser.py#L226-L247](https://github.com/HearthSim/python-hslog/blob/015c0dec197779c90cd3131ecda2c990292342b6/hslog/parser.py#L226)). Other cross-checks: the `LoadingScreen.log` scene `currMode=BACON`, BG card IDs such as `TB_BaconShop_HERO_PH` placeholder heroes, and `BACON_*` tags on GameEntity. For Duos, use `GameType=GT_BATTLEGROUNDS_DUO*` and/or `BACON_DUO_TEAM_ID` / `BACON_DUO_TEAMMATE_PLAYER_ID` on player entities.

### 3.3 Match start and end
- **Scene (LoadingScreen.log):** `LoadingScreen.OnSceneLoaded() - prevMode=HUB currMode=BACON` (BG lobby), then `OnScenePreUnload() - prevMode=BACON nextMode=GAMEPLAY`, then `Gameplay.Start()` (live). HDT regexes: `prevMode=(?<prev>\w+).*currMode=(?<curr>\w+)` and `...nextMode=` ([HDT/Hearthstone Deck Tracker/LogReader/LogConstants.cs](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/LogReader/LogConstants.cs)). HSTracker filters LoadingScreen for `LoadingScreen.OnSceneLoaded`, `Gameplay`, `LoadingScreen.OnScenePreUnload` and `MulliganManager.HandleGameStart`.
- **Start:** `CREATE_GAME`. HSTracker resets on it ([PowerGameStateParser.swift#L1544](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/Parsers/PowerGameStateParser.swift#L1544)), and python-hslog ignores everything before the first `CREATE_GAME`.

## 4. Battlegrounds state you can extract

**Entity model (live log + HDT).** The local player is one Player entity (PlayerID=2 in the live game). A **single opposing Player entity** (PlayerID=10 in the live game, `GameAccountId=[hi=0 lo=0]`, named after the bartender, e.g. "LazyTitan") owns **Bob's shop minions during recruit and the current opponent's board during combat**:
- Shop minions: `[entityName=Dune Dweller id=382 zone=PLAY zonePos=3 cardId=BG31_815 player=10]`.
- Combat copies are created as `FULL_ENTITY` in `SETASIDE` and then get `CONTROLLER=10` / `ZONE=PLAY`. Example: `BLOCK_START BlockType=ATTACK Entity=[entityName=Glim Guardian id=598 zone=PLAY zonePos=1 cardId=BG29_888 player=10]`.

All eight lobby heroes exist as hero entities, mostly in SETASIDE, e.g. `[entityName=The Great Akazamzarak id=231 zone=SETASIDE ... cardId=TB_BaconShop_HERO_21 player=10] tag=PLAYER_TECH_LEVEL value=1`. Each combat and each shop phase creates **new** entity IDs, so IDs are not stable across turns.

Legend: **LOG** = reliably in Power.log (PowerTaskList). **LOG\*** = in the log, but interpreting it needs heuristics. **MEM** = memory reading (HearthMirror) is needed. **N/A** = not available locally.

## 5. HearthMirror (memory reading) on macOS

### 5.1 What HSTracker reads from memory
The `MirrorHelper` API ([HST/HSTracker/HearthMirror/MirrorHelper.swift](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/HearthMirror/MirrorHelper.swift)) covers:
- Identity and session: BattleTag, account ID and region, **log session dir**, spectating, game type, match info (player names/IDs, medals), format, game server info.
- Battlegrounds: rating info and rating change, **available/unavailable races**, selected BG game mode, **lobby info** (players, names, account IDs, game UUID), **teammate board state (Duos)**, leaderboard hover.
- UI and choices: card choices, special shop choices, discover state, big-card and mulligan tooltip state, board state, scene manager state, shop/journal/popup/friends-list/game-menu visibility.
- Non-BG: collection, decks, arena, dungeon runs, mercenaries.

**For BG from logs alone you lose:** available tribes (use a heuristic instead), rating/MMR, lobby player names, the Duos teammate's recruit-phase board, and UI state such as hover and whether choices are visible. **You keep:** game type, hero options and pick, and all in-game state. The one hard HSTracker-specific dependency is that **HSTracker finds the log folder only through the mirror**. A log-only tool must discover the folder itself (§1.3).

### 5.2 Licence and availability
- **HearthMirror is a closed, prebuilt binary.** The HSTracker Xcode build phase "Download HearthMirror" runs `wget "https://libs.hearthsim.net/hstracker/$SHA1/HearthMirror.framework.zip"` (plus a dSYM zip) with the SHA from `HSTracker/HearthMirror-version.txt` (currently `912e88ea97532407245eabc51913a9c682144566`). It unpacks the framework into the git-ignored `downloaded-frameworks/` ([HST/HSTracker.xcodeproj/project.pbxproj#L6837](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker.xcodeproj/project.pbxproj#L6837); [HST/.gitignore](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/.gitignore)). No source is in the repo. HDT likewise uses a `HearthMirror` assembly (`using HearthMirror;` / `Reflection.Client.*`), and Firestone ships `OverwolfUnitySpy.dll` / `UnitySpy.HearthstoneLib.dll` binaries ([FS/overwolf-plugins/](https://github.com/Zero-to-Heroes/firestone/tree/0a30f066eb77a417637d95cec86444456f607ba1/overwolf-plugins)), which are Windows only. Firestone's electron-app loads .NET through Edge.js. **Treat HearthMirror as unavailable for third-party use** unless HearthSim licenses it.
- **Permissions (macOS):**
  - `MirrorHelper.initMirror` calls `acquireTaskportRight()` before attaching to the Hearthstone PID ([MirrorHelper.swift#L38-L44](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/HearthMirror/MirrorHelper.swift#L38)). ## 6. Pitfalls

1. **Folder per session, not rotation.** Each launch writes a new `Logs/Hearthstone_<timestamp>/`, so re-discover the folder when HS restarts. HSTracker restarts its readers when the app launches or terminates, and HDT re-checks the folder every 5 s ([LogFileWatcher.cs#L40](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/HearthWatcher/LogReader/LogFileWatcher.cs#L40)). HSTracker's `LogReader.init` **deletes** a `<name>.log` it finds that Hearthstone does not hold open; don't copy this if you want to keep history.
2. **Catch-up and entry point.** On start, HSTracker scans backwards for the last `tag=STATE value=COMPLETE` / `End Spectator` in Power.log and the last `Gameplay.Start` in LoadingScreen.log, then starts from the later of the two. This avoids replaying finished games ([LogReaderManager.swift `entryPoint()`](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogReaderManager.swift)). Polling interval: `updateDelay = 0.05` s.
3. **Size and performance.** The live BG `Power.log` reached 3.6 MB by BG turn 3–4 (about 5 min), and `Zone.log` reached 6.2 MB. HDT caps its queue at `MAX_LOG_LINE_BUFFER = 100_000` lines because of "very late Battlegrounds matches, especially when restarting HDT or when a combat has excessively many actions" ([LogFileWatcher.cs#L28-L34](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/HearthWatcher/LogReader/LogFileWatcher.cs#L28)). python-hslog ships a `BattlegroundsLogFilter` that drops uninteresting ATTACK/DEATHS blocks and blacklisted tags to cut BG log size ([HSLOG/hslog/filter.py](https://github.com/HearthSim/python-hslog/blob/015c0dec197779c90cd3131ecda2c990292342b6/hslog/filter.py)). Read incrementally from a byte offset and filter by prefix before running regexes (both trackers do). Don't enable `Zone`/`Gameplay` unless needed. Write `client.config` `FileSizeLimit.Int=-1` (§1.4).
4. **Encoding and corruption.** Treat the logs as UTF-8, since BattleTags and localized card names are non-ASCII. HSTracker decodes UTF-8 but computes its initial offset with `.ascii`, which is a latent bug ([LogReader.swift `findInitialOffset`](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/HSTracker/Logging/LogReader.swift)). Lines can contain **binary garbage**: python-hslog's `CORRUPT_SHOW_ENTITY` fixture has `\x01\x00\x10...` in the middle of a BG `SHOW_ENTITY` ([HSLOG/tests/data.py](https://github.com/HearthSim/python-hslog/blob/015c0dec197779c90cd3131ecda2c990292342b6/tests/data.py)). A partial last line may be read mid-write, so buffer until a newline (HSTracker drops lines of 20 characters or fewer).
5. **Timestamps have no date.** Handle midnight rollover (HDT `LogLine.cs`). python-hslog has fixtures for unroundable and repeated timestamps.
6. **Entity IDs.** They are monotonic within a game, but BG creates **new IDs for every shop refresh and every combat copy**, and IDs run into the thousands (fixtures show ids of 9000 and more). Never key long-lived state (such as "my minion X") on entity ID across phases. Use card ID + position, or `COPIED_FROM_ENTITY_ID` / `LINKED_ENTITY` / `BACON_TRIPLE_UPGRADE_MINION_ID` where available. The bartender and opponent share one Player slot (§4).
7. **Hidden information.** Opponent hand and secret entities are `UNKNOWN ENTITY [cardType=INVALID]` with an empty `CardID`. The opponent board appears only at combat, and other lobby players' boards appear only when they fight you. HDT's `RewoundEntityCreationFilter` exists because a rewind leaves created entities referenced by later lines ([HDT/Hearthstone Deck Tracker/LogReader/RewoundEntityCreationFilter.cs](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/LogReader/RewoundEntityCreationFilter.cs)).
8. **Timing of the combat-simulation input (BobsBuddy).**
   - **Trigger:** in solo, GameEntity tag `2022` going 1→0 (PowerTaskList) calls `BobsBuddyInvoker.StartCombat()`. It is guarded so that it runs only if GameEntity `TURN` > the TURN at shopping start. This rejects spurious "combats" that appear inside a shopping turn ([TagChangeActions.cs#L203-L228](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/LogReader/Handlers/TagChangeActions.cs#L203)). In Duos, tag `3533` 1→0 triggers `SnapshotBattlegroundsBoardState()` and a Duos `StartCombat()`.
   - **Snapshot:** `StartCombat` calls `SnapshotBoardState(turn)` **immediately** from the tracked entity state, which already contains the opponent's `FULL_ENTITY` board. It then waits `StateChangeDelay = 500` ms and gives up if the state changed. There is an extra `LichKingDelay = 2000` ms if Reborn Rite is active. Simulation runs for 10,000 iterations within `MaxTime = 1500` ms ([BobsBuddyInvoker.cs#L31-L38, #L195-L260, #L886-L960](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/BobsBuddy/BobsBuddyInvoker.cs#L195)).
   - **Snapshot contents:** `availableRaces` (from **memory**), `DamageCap`, anomaly, both players' heroes, hero powers, quests, trinkets, minions, enchantments and per-player counters.
   - **Reconnects:** a reconnect invalidates the snapshot (`_reconnectCounter`).
   - **Firestone** does the same from its event stream (`BATTLEGROUNDS_PLAYER_BOARD`) and fills Duos teammates from memory ([FS bgs-player-board-parser.ts](https://github.com/Zero-to-Heroes/firestone/blob/0a30f066eb77a417637d95cec86444456f607ba1/libs/game-state/src/lib/services/game-events/event-parser/battlegrounds/bgs-player-board-parser.ts)).
9. **Unnamed and renumbered tags after patches.** Critical BG phase tags (2022, 3533, 3148, 3479) have no enum name in HearthDb or python-hearthstone, and the client prints them as numbers. Blizzard patches add tags often; python-hslog even handles a stray `EOE` enum value. Both trackers regularly ship fixes after patches, e.g. HSTracker 1.6.31: "Make basic tracking work again after patch 17.2" ([HST CHANGELOG](https://github.com/HearthSim/HSTracker/blob/c723bfd4a7f05ff4d2b7809ae95fce9a9a066ac4/CHANGELOG.md)). Parse tags by **numeric ID** with a name map, tolerate unknown names and numbers, and keep the enum map updatable (e.g. from python-hearthstone or HearthDb).
10. **Game-type misreads.** Memory can report a solo type during Duos (§3.2). A log-only reader avoids this by using `DebugPrintGame GameType=` plus `BACON_DUO_TEAM_ID`.
11. **Reconnect or mid-game attach.** Logs written after a BG reconnect are called "likely invalid" by HDT ([GameEventHandler.cs#L209](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/GameEventHandler.cs#L209)). On reconnect the client re-sends a full state (`CREATE_GAME` with every entity), so rebuild state from scratch.
12. **Stale per-opponent tags.** When the next opponent changes, HDT zeroes `TAVERN_SPELL_*_INCREASE` and `BACON_BLOODGEMBUFF*VALUE`, because a reveal only writes non-zero values ([TagChangeActions.cs#L1702-L1717](https://github.com/HearthSim/Hearthstone-Deck-Tracker/blob/ef8ab6e8380a647d757eec203d310395d6b97ae0/Hearthstone%20Deck%20Tracker/LogReader/Handlers/TagChangeActions.cs#L1702)).
